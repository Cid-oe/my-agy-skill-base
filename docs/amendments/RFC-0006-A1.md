# Amendment RFC-0006-A1 — Event Bus: governed open namespaces

**Target:** RFC-0006 (Event Bus) · **Status:** Proposed · **Severity:** Major

## Problem

RFC-0006 §3.2 declares a **closed** event-type enum ("a producer publishing
an event type not in this table is a schema violation… new event types
require an RFC amendment") and §5.1 an explicit producer allowlist (Artifact
System, RuntimeState only). RFC-0010/0012/0013/0014/0015 all publish their
own namespaces (`memory.*`, `tool.*`, `reflection.*`, `learning.*`,
`observability.*`) and use a topic grammar inconsistent with §3.1's examples
(`memory.written` vs `runtimestate.status.transitioned`). RFC-0006 also
labels Scheduler/Executor as "reserved" producers (§3.3) — but the actual
RFC-0007 never adopted the bus at all. Finally, §header/§1.4 point at
"Observation Engine (RFC-0009)" and "Resource Manager (RFC-0010)" — both
numberings wrong post-reconciliation.

## Reason

The closed enum was deliberate minimality, but the corpus has since
legitimately needed five more producer domains; the mechanism for that
growth (§3.2's own "RFC amendment" clause) is this amendment. The Scheduler
adoption question is resolved in RFC-0007-A1; this amendment registers the
namespaces both sides need.

## Impact

Enum opens under governance; producers registry defined; topic grammar
canonicalized with an alias table so existing draft text need not be edited.

## Resolution

**R1 — Producer & namespace registry.** The closed table is replaced by a
**registry of producer namespaces**, each owned by its subsystem RFC, which
owns its event types and payload schemas (registered as files under
`schemas/events/<domain>/`). Initial registry:

| Namespace | Owner RFC | Notes |
|---|---|---|
| `artifact.*` | RFC-0004 | payload shapes per RFC-0004-A1 R2 |
| `runtimestate.*` | RFC-0005 | as §3.2 (status/mutation/checkpoint/blocked) |
| `scheduler.*` | RFC-0007 | per RFC-0007-A1 R5 |
| `executor.*` | RFC-0008 | per its Appendix C, normalized to grammar |
| `memory.*` | RFC-0010 | |
| `planner.*` | RFC-0011 | |
| `tool.*` | RFC-0012 | |
| `reflection.*` | RFC-0013 | |
| `learning.*` | RFC-0014 | |
| `observability.*` | RFC-0015 | internal dropped-signal metrics |
| `escalation.*` | *(reserved)* | unowned until the escalation owner RFC exists (see RFC-0000 registry, RFC-0021) |

Ingestion authorization (§5.1) becomes: `producerId` must be the registered
owner of the namespace it publishes under. Adding a namespace = an
amendment to this registry (the same bar as before, but extensible by
design).

**R2 — Topic grammar.** Canonical grammar:
`<domain>.<object>.<verb>[.<correlationId>]`, prefix-subscribable at every
level. Existing names are **grandfathered via alias table** (normalized at
ingestion, both forms delivered until `schemas/events/` is authoritative):

| Legacy (draft text) | Canonical |
|---|---|
| `memory.written` / `memory.read` / `memory.deleted` / `memory.consolidated` / `memory.expired` | `memory.entry.written` / `.read` / `.deleted` / `.consolidated` / `.expired` |
| `memory.snapshot_taken` | `memory.snapshot.taken` |
| `tool.invocation.started` etc. | already canonical |
| `scheduler.execution.completed` etc. | already canonical (defined by RFC-0007-A1 R5) |
| `ArtifactCreated` et al. (§3.2 CamelCase) | `artifact.artifact.created` et al. (RFC-0004-A1 R2) |

**R3 — Trace context.** The envelope gains optional `traceId?: string` and
`spanId?: string` (W3C-compatible), satisfying RFC-0015's correlation
dependency (its §19) without breaking §2.2's schema.

**R4 — Reference corrections.** "Observation Engine (RFC-0009)" →
"Observability (RFC-0015)"; "Resource Manager (RFC-0010)" → "Resource
Manager (future RFC-0016)". (RFC-0009's number is retired — see its
retirement record.)

## Compatibility

§4 delivery semantics, §7 backpressure, §9 replay, §10 partitioning all
unchanged. The enum's fail-closed ingestion rule now consults the registry
instead of a fixed table — same enforcement, larger table.

## Migration

None at runtime (nothing implemented). Draft-RFC prose using legacy names
stands; the alias table is the compatibility layer until schemas land.
