# Amendment RFC-0015-A1 — Observability: trace context & renumbering

**Target:** RFC-0015 (Observability) · **Status:** Proposed · **Severity:** Minor

## Problem

1. §19 depends on optional `trace_id`/`span_id` in event envelopes, which
   published RFC-0006 §2.2 does not define.
2. §4 states RFC-0006 is consumed "as the canonical operational event
   stream," but the Scheduler (a primary signal source) did not publish —
   resolved by RFC-0007-A1 R5, needing only acknowledgment here.
3. §21 suggestions collide with the reserved block (RFC-0016–0020).

## Reason

Reference hygiene; both substantive dependencies are granted elsewhere.

## Impact

Two acknowledgments; renumbering. No Observability behavior changes.

## Resolution

**R1 — Trace context granted.** RFC-0006-A1 R3 adds optional `traceId`/
`spanId` to the event envelope; correlation quality per §19 improves
accordingly. Tool-runtime `TraceContext` (RFC-0012 §8.4) composes with it.

**R2 — Scheduler signals available.** `scheduler.task.*` and
`scheduler.execution.*` events are published per RFC-0007-A1 R5;
Observability subscribes per §4 unchanged. The retired "RFC-0009 /
Observation Engine" label resolves to this RFC (see the RFC-0009 retirement
record).

**R3 — Renumbering.** Credential & Secret Hygiene → folds into RFC-0017
scope; Incident Management, Observability Federation, Formal Decision
Journal Schema, Observability Cost Controls → unassigned pool (RFC-0000
§8).

## Compatibility / Migration

None beyond reference updates.
