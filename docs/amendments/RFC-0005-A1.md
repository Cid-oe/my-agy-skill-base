# Amendment RFC-0005-A1 — Runtime State: parallel fix, scoped records, primitives

**Target:** RFC-0005 (Runtime State) · **Status:** Proposed · **Severity:** Major

## Problem

1. RFC-0005 §18.1 declares its own schema unfinished: `currentNode: string |
   null` cannot represent concurrent nodes — "This RFC should not be
   considered final until `currentNode` is corrected to `currentNodes[]`."
2. RFC-0008 (§8.1–8.6, Appendix A) stores Execution Records, Attempt
   Records, command journals, and leases in Runtime State as **per-key CAS
   records with watch and lease primitives** — a scoped key-value model
   RFC-0005 does not define (its unit is one object per execution, §3.2,
   §8.2). RFC-0008 §19.6 flags this; it was never resolved.

## Reason

The correction in (1) is mandated by the RFC itself. For (2), generalizing
Runtime State to scoped child records is the smaller move: RFC-0005's
mutator discipline, revision semantics, and ownership tables are preserved
verbatim, and RFC-0008's needs are already designed around per-record
granularity.

## Impact

One field type change (pre-implementation), one storage-model
generalization, two primitive definitions. RFC-0005's §12/§13 mutator
tables remain the authority on *who* may write *what*.

## Resolution

**R1 — `currentNodes: string[]`** replaces `currentNode` (empty = none
running). State-machine prose references to "a Node" in the singular are
read as "each running Node." Re-verification pass per §18.5 is a Phase-1
acceptance criterion for the RuntimeState implementation.

**R2 — Scoped state domains.** A RuntimeState **state domain** is the
namespace `runtimestate/{executionId}/` containing:
- the **root ExecutionState record** — RFC-0005 §3.2 schema, unchanged
  except R1; and
- **child records** (`execution-record`, `attempt-records/{id}`,
  `command-journal`, `lease`, …) owned by designated mutators (§12–§13) —
  Executor-owned child record types are enumerated by RFC-0008 §8.

**R3 — Granular CAS.** Every record carries its own `revision`; CAS applies
per record (RFC-0008's exactly-once-bookkeeping requirement). The root
record additionally maintains `domainRevision` (bumped by any child
commit) so whole-domain snapshots/checkpoints (§9) remain atomic-consistent
without serializing unrelated child writes. Conflict-resolution table (§8.3)
applies per record.

**R4 — Primitives.** The mutation API gains `watch(prefix, callback)`
(ordered, at-least-once, RFC-0006-consistent delivery semantics) and lease
records `{holder, fenceToken, expiresAtMonotonic}` with CAS
acquire/renew/expire and write-time fence checks — the semantics RFC-0008
§8.6/§11.7 specifies, now owned by RuntimeState rather than re-invented per
consumer. CancellationState stays cooperative (§3.7).

**R5 — Terminology.** "Checkpoint" (RuntimeState §9) = durable
`RuntimeStateSnapshot` artifact of the state domain. RFC-0008's stream
checkpoints (§8.4: per-stream durable offsets) are **stream offsets**, a
distinct concept owned by RFC-0008. Documents must not use the bare word
"checkpoint" for both (RFC-0005 §14.3's hazard, closed).

## Compatibility

Pre-implementation, the field change is free. The single-object model of
§3.2 remains the correct mental model for readers; R2 generalizes storage,
not semantics.

## Migration

RFC-0008 needs no change to its data structures (they become the child
records R2 anticipates). Any future consumer wanting root-object semantics
uses the root ExecutionState record only.
