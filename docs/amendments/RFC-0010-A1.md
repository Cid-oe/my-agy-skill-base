# Amendment RFC-0010-A1 — Memory System: substrate correction & phasing

**Target:** RFC-0010 (Memory System) · **Status:** Proposed · **Severity:** Moderate

## Problem

1. RFC-0010 §"Dependency on RFC-0008 and RFC-0009" assumes "RFC-0008 defines
   model routing and RFC-0009 defines token budgeting (this is assumed, not
   confirmed)" — both false. RFC-0008 is the Executor; RFC-0009 is retired
   (Observation Engine never materialized there; Observability is RFC-0015).
2. RFC-0013 §19.3 requires RFC-0010's Reflection Memory tier to adopt
   RFC-0013's `Lesson` structure as canonical; the dependency is
   unacknowledged here.
3. §20.1 itself warns the seven-tier model is operationally heavy for early
   deployment but the RFC body mandates all seven.

## Reason

Assumption (1) was written blind (same generation as RFC-0011–0015's other
substrate guesses); the corrections preserve every memory-system behavior.
(2) and (3) are cross-reference and phasing discipline, not redesign.

## Impact

Reference changes; a schema-ownership note; a normative phased-subset
statement. No tier, algorithm, or interface changes.

## Resolution

**R1 — Substrate corrections.** Model context-window limits for the
Compression Engine are obtained from the **`model-router` skill** (interim)
and, once chartered, **RFC-0018 (Model Registry & Router)** — replacing the
"RFC-0008" assumption. Token budgets for compressed retrieval come from the
**`token-budget` skill** (interim) and, once chartered, **RFC-0016
(Resource Manager & Execution Ledger)** — replacing the "RFC-0009"
assumption. ContextPolicy (RFC-0003 §7.4) remains the gate.

**R2 — Lesson schema ownership.** The Reflection Memory tier stores entries
using the **`Lesson` structure owned by RFC-0013 §8.4** (confirmed there by
RFC-0013-A1 R2). RFC-0010 remains the owner of *tier semantics*
(lifecycle, consolidation, decay); RFC-0013 owns the *entry schema* for
lesson-type entries. See Ownership Matrix.

**R3 — Phased tiers (normative).** Implementations MAY ship Phase 1 with
**Working, Episodic, Semantic, Long-term** only, provided: Project Memory
is served as policy-scoped views over Semantic/Long-term, and User Memory
is served as policy-isolated scopes over the same stores with its consent
ledger intact. The seven-manager topology remains the full-capability
target per §5.1. This converts §20.1's self-assessment into an allowed,
defined configuration rather than "a half-broken one."

**R4 — Event topics.** `memory.*` events publish under RFC-0006-A1's
registry with canonical aliases (`memory.entry.written`, etc.). §19.3's
request for a namespace registry is thereby granted.

## Compatibility

All interfaces unchanged. Tier semantics unchanged.

## Migration

Implementers target R3's Phase-1 subset first; Reflection/Project/User
managers activate behind the same public interface when needed.
