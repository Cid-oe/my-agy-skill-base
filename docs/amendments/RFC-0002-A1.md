# Amendment RFC-0002-A1 — Skill Registry & Loader: manifest extensions & conventions

**Target:** RFC-0002 (Skill Registry & Loader) · **Status:** Proposed · **Severity:** Major

## Problem

Four later RFCs require manifest fields RFC-0002 does not define:
`methods` (RFC-0011 §19.2), `tool_dependencies` (RFC-0012 §19.1),
`compensations` + retryability declaration (RFC-0008 §19.5), `memory_profile`
(RFC-0010 §4). Additionally, the entire shipped skill pack declares no
`entryPoint` code file — these are prompt-defined skills whose executable
content is the SKILL.md body itself — and the pack carries a legacy
`alwaysApply` field unknown to the schema.

## Reason

All four fields are already specified in detail by their consuming RFCs;
this amendment only registers their home in the manifest schema. The
prompt-skill convention resolves the pack's validation failure without
forcing code artifacts onto every skill.

## Impact

Manifest schema gains four *optional* blocks and one convention. No required
field changes; existing manifests validate unchanged.

## Resolution

**R1 — Optional blocks (all default empty/absent):**

```yaml
methods:            # RFC-0011 §9.5 shape; indexed by applies_to_task_type
  - method_id: string
    ...
tool_dependencies:  # RFC-0012 §4 shape
  - capability_name: string
    version_constraint: string
compensations:      # RFC-0008 D-7; absent ⇒ skill is non-rollbackable
  - artifact_type: string
    inverse: string        # skill id or capability invoked to undo
retryability:
  class: IDEMPOTENT | AT_LEAST_ONCE | NON_IDEMPOTENT   # RFC-0008 §4.2
memory_profile:      # RFC-0010 §4 shape (footprint, tiers, consolidation hints)
  expected_footprint: low | medium | high
  reads: [tier]
  writes: [tier]
```

The Registry indexes `methods[].applies_to_task_type` exactly as it indexes
`produces` (inverted index), answering RFC-0011 §15.2's scaling requirement.

**R2 — Prompt-skill entryPoint convention.** For skills whose executable
content is the SKILL.md instruction body (no code entry point),
`entryPoint: SKILL.md` is valid: the package's entry point is the skill
definition itself, interpreted by the executing agent. Path-traversal and
existence checks apply unchanged. Code-bearing skills keep code entry points
and are sandboxed per §14.5 as written.

**R3 — Unknown-field policy.** Fields not in the schema (e.g. legacy
`alwaysApply`) are **warnings, not errors**, at `local` trust; they are
stripped from the parsed manifest presented to the Resolver. At trust
`verified`, unknown fields remain warnings but are included in the checksum
scope.

**R4 — `escalateTo`/`exclusiveWith` combination.** Per RFC-0001-A1 R3, a
manifest whose `escalateTo` names an `exclusiveWith` partner is valid; drop
any validator wording that could be read to reject it.

**R5 — `exclusiveWith` symmetry** remains as written (§3.3/§7.5,
auto-symmetrize with warning). The shipped pack is now symmetric; the
auto-symmetrize path remains as defense in depth.

## Compatibility

Additive only. The v2 skill pack (post Phase-0 repair) validates at `local`
trust: `id` = `name`, `version: 2.0.0`, `entryPoint: SKILL.md`, checksum not
required at `local`.

## Migration

None required for existing manifests. Skills adopting `compensations` before
RFC-0008's implementation simply carry unused metadata.
