# Amendment RFC-0007-A1 — Scheduler: reference repair & contract unification

**Target:** RFC-0007 (Scheduler) · **Status:** Proposed · **Severity:** Major

## Problem

1. **Numbering collision:** RFC-0007 §0/§4.1/§19 refer to "RFC-0004:
   Execution Runtime"; the real RFC-0004 is the Artifact System. Its
   `Depends on:` header lists only RFC-0001–0003 although its text depends
   on artifacts (§7.2, §10.3), runtime state (§10.1) and a delivery channel.
2. **Dispatch fork:** §11 specifies `IExecutionRuntime.dispatch/cancel/
   heartbeat` with Scheduler-granted leases; RFC-0008 specifies
   `Dispatch(Order)` admission with Executor-owned lease+fence. Two lease
   models, two completion contracts.
3. **Cancellation fork:** §11.4 makes a task `CANCELLED` on *issuing* cancel;
   RFC-0008 §11.6 defines cooperative `CANCEL_REQUESTED → CANCELLING →
   CANCELLED` with grace and force-abort.
4. **Event Bus non-adoption:** RFC-0006 was justified by the Scheduler's
   needs; actual RFC-0007 never references it, and downstream RFCs (0013)
   subscribe to `scheduler.*` events that RFC-0007 never defined.

## Reason

RFC-0007 was authored without sight of RFC-0004–0006 (its own §0) and
RFC-0008 was authored against an assumed Scheduler. The Executor's boundary
contract is the more complete of the two (idempotent dispatch, admission,
Hold, fencing) and matches RFC-0005-A1's primitives; the Scheduler keeps
everything it uniquely owns: queues, ordering, fairness, reservations,
dependency satisfaction.

## Impact

§11 is replaced by adoption of RFC-0008's contract (via reference, not
rewrite of RFC-0008). Task state machine gains a `CANCELLING` state. The
Scheduler's Lease concept is retired in favor of Reservation + Executor
lease.

## Resolution

**R1 — Reference & dependency corrections.** All "RFC-0004 (Execution
Runtime)" references → "RFC-0008 (Executor)"; "Artifact Registry" → "RFC-0004
(Artifact System)". `Depends on:` becomes: RFC-0001 (type: ExecutionPlan),
RFC-0003 (type: PolicyDecision), RFC-0004 (runtime), RFC-0005 (runtime),
RFC-0006 (runtime, per R5), RFC-0008 (runtime: dispatch).

**R2 — Dispatch contract.** §11's interface is superseded by RFC-0008 §7:
the Scheduler's dispatch unit is the **Execution Order** (`Order = {orderId,
planId, stepId, skillRef, inputs, budget, …}`, RFC-0008 §7.1). Idempotency
is on `orderId`; `Hold(reason)` is the backpressure signal consumed by the
Scheduler's Ready-Queue backpressure (§5.7). §11.5 heartbeats are subsumed
by RFC-0008's lease renewal; the Scheduler's lease-expiry behavior (§4.3)
is re-expressed as: an Executor-reported lease loss/failure completion is
handled by the Retry Manager exactly as a failure signal.

**R3 — Cancellation.** Task state machine: on issuing cancel the Task
enters **`CANCELLING`** (not `CANCELLED`); it reaches terminal `CANCELLED`
on the Executor's terminal `execution.cancelled` event **or** on
cancellation-budget expiry (deterministic fallback preserving §11.4's
no-indefinite-wait intent). RFC-0008's cooperative grace/force-abort remains
the execution-side semantics; the Scheduler never assumes preemption.

**R4 — Ownership statement.** Canonical split (matches both RFCs' §1.3
non-goals): *Scheduler owns when/where/in-what-order; Executor owns
how/whether-at-all (admission) and all execution-side state.* The
Scheduler's §12 checkpoint is renamed **Scheduler State Snapshot** (its own
queue/lease bookkeeping) to avoid collision with RFC-0005 checkpoints and
RFC-0008 stream offsets (per RFC-0005-A1 R5).

**R5 — Event Bus adoption.** The Scheduler subscribes to `runtimestate.*`
and `artifact.*` (per RFC-0005 §19's original intent) for observation, and
**publishes** `scheduler.task.{dispatched,completed,failed,cancelled,
retried}` and `scheduler.execution.completed|failed|cancelled` under
RFC-0006-A1's registry — the topics RFC-0013/0015 already consume. The
dispatch/completion **control** channel with the Executor remains direct
(deterministic cycle semantics, §3.9); the bus carries observation, not
control. This is the documented equivalence RFC-0006 §0 anticipated.

**R6 — Retry scope.** The Retry Manager (§3.10) handles *queue-level*
re-dispatch (lease loss, resource signals, Hold expiry). Attempt-level
retry inside an Execution belongs to RFC-0008 §11.4; tool-level retry to
RFC-0012 §6.8. `RetryPolicy` (RFC-0003 §7.8) remains the single *decision*
authority at every layer (see Ownership Matrix, `docs/phase-0/04`).

## Compatibility

Task states `PLANNING…FAILED` unchanged except added `CANCELLING`. The six
queues, fairness aging, critical-path tie-breaks, backpressure — all
unchanged.

## Migration

§11 readers: treat RFC-0008 §7 + this amendment's R2/R3 as the operative
Scheduler↔Executor contract. §12 readers: see R4 rename.
