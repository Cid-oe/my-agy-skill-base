# RFC-0003a: Policy Conflict Resolution Order

**Status:** Accepted (Amendment to RFC-0003)  
**Subsystem:** Policy Engine  
**Author:** Lead Systems Engineer  

---

## 1. Problem Statement
RFC-0003 specifies policy evaluations producing `allow` or `deny` decisions. When multiple policies evaluate the same request (e.g. general security policy vs budget policy vs user override), the precedence order must be deterministic and safe against privilege escalation.

## 2. Precedence Specification

1. **Deny-Overrides Principle:**
   - If any active applicable policy evaluates to `DENY`, the aggregated decision is `DENY`, regardless of other `ALLOW` evaluations.

2. **Priority Ordering:**
   - Policies carry a strict integer priority (`1` = highest, e.g. Hard Kernel Safety, `100` = Standard Governance, `1000` = Soft Heuristic).
   - Higher priority policies evaluate first.
   - A `DENY` from any level immediately terminates evaluation and emits a `PolicyDecision(decision='deny', reason=...)`.

3. **Explicit Override Authority:**
   - Only a cryptographically verified operator override with explicit `admin:override` capability can bypass a lower-tier policy denial, provided Kernel Safety (Priority 1) invariants are not violated.
